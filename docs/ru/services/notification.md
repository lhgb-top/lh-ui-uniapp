# Notification

Глобальный сервис уведомлений. Показывает карточки с заголовком и содержимым в углах области просмотра, обычно для обратной связи о результате, требующей внимания пользователя. Как и Message / Loading, использует **шаблон точки монтирования**——мини-программа не может создавать DOM через JS, поэтому на странице сначала нужно разместить компонент точки монтирования.

## Размещение точки монтирования

Разместите один раз на страницах, где нужны уведомления (или в постоянном корневом компоненте-обёртке):

```vue
<template>
  <lh-config-provider>
    <view><!-- содержимое страницы --></view>
    <lh-notification />
  </lh-config-provider>
</template>
```

::: danger Отсутствие точки монтирования вызывает предупреждение
Если вызвать `useLhNotification()`, но на странице нет `<lh-notification />`, в процессе разработки будет выведено явное предупреждение через `console.error`, **тихой деградации нет**. Как и в Message: тихая деградация превратила бы «вызов выглядит успешным, но ничего не происходит» в скрытую ошибку.
:::

## Вызов

```ts
import { useLhNotification } from '@lh-ui/uniapp'

const notification = useLhNotification()

notification.success({ title: 'Уведомление об успехе', content: 'Документ записан в облако' })
notification.info({ title: 'Информационное уведомление' })
notification.warning({ title: 'Предупреждение' })
notification.danger({ title: 'Критическое уведомление' })

// Каждый угол — независимый контейнер
notification.info({ title: 'Левый верхний угол', position: 'top-left' })

// Без автозакрытия, закрытие вручную
const handle = notification.warning({ title: 'Постоянное предупреждение', duration: 0 })
handle.close()

// закрыть все
notification.closeAll()
```

## Методы

| Метод | Описание | Параметры |
| --- | --- | --- |
| (прямой вызов) | `notification(options)` открывает уведомление | `(options: LhNotificationOptions)` |
| success / info / warning / danger | Открывает уведомление соответствующего семантического типа | `(options: LhNotificationOptions)` |
| close | Закрывает уведомление с указанным id | `(id: number)` |
| closeAll | Закрывает все | — |
| config | Изменяет глобальные значения по умолчанию | `(config: LhNotificationConfig)` |

## LhNotificationOptions

| Свойство | Описание | Тип | По умолчанию |
| --- | --- | --- | --- |
| title | Заголовок (обязательный) | `string` | — |
| content | Содержимое | `string` | — |
| type | Семантический тип | `'success' \| 'info' \| 'warning' \| 'danger' \| 'error'` | `'info'` |
| duration | Миллисекунды до автозакрытия; 0 — без автозакрытия | `number` | `4500` |
| position | Позиция появления | `'top-right' \| 'top-left' \| 'bottom-right' \| 'bottom-left'` | `'top-right'` |
| showClose | Показывать кнопку закрытия | `boolean` | `true` |
| sx | Свойства быстрой разметки sx | `LhSxProps` | — |
| onClick | Колбэк клика по карточке (карточка получает семантику кнопки) | `() => void` | — |
| onClose | Колбэк после закрытия (автоматического или ручного) | `() => void` | — |

::: tip Тип error
`error` — псевдоним семантики `danger` (`LhNotificationType` в share core его включает). Методы сервиса, как и в plus, предоставляют только success / info / warning / danger; для error вызывайте напрямую `notification({ title: '...', type: 'error' })`.
:::

## Глобальная конфигурация

```ts
const notification = useLhNotification()
notification.config({ duration: 3000, offset: 24 })
```

| Параметр | Описание | По умолчанию |
| --- | --- | --- |
| duration | Длительность автозакрытия по умолчанию в миллисекундах; 0 — без автозакрытия | `4500` |
| offset | Отступ от края области просмотра (px) | `20` |

## Поведение

- **Четыре независимых контейнера по углам**: записи группируются по `position` и складываются в хронологическом порядке внутри одного угла (в двух нижних углах используется `column-reverse`, новые уведомления прижимаются к нижнему краю); интервал стекирования управляется переменной стилей `--lh-notification-gap` (по умолчанию 16px).
- **Автозакрытие**: удаляется автоматически через `duration` миллисекунд и вызывает `onClose`; `duration: 0` означает постоянное отображение.
- **Клик по карточке**: не закрывает (как в plus), только вызывает `onClick`; закрытие происходит только через кнопку закрытия или автоматический таймер.
- **Доступность**: контейнеры углов получают `role="region"` + `aria-live="polite"`; карточки с `onClick` получают `role="button"`; кнопка закрытия несёт доступное имя из ключа языкового пакета `notification.close` (уже включён в языковые пакеты share, обновляется при смене языка).

## Отличия платформы (от версии Vue3)

- **Шаблон точки монтирования**: plus монтирует host в `document.body` через `createApp`; у мини-программы нет `document`, поэтому используется «модульный singleton store + компонент точки монтирования `<lh-notification />` на странице», API предоставляется через `useLhNotification()` (в plus — прямой вызов `LhNotification` + регистрация через install).
- **Нет `appendTo`**: веб-версия может выбирать контейнер монтирования; у мини-программы такого понятия нет, позицию определяют фиксированные угловые контейнеры, отрисованные компонентом точки монтирования.
- **Упрощённые анимации появления/исчезновения**: plus использует `TransitionGroup` для скользящего появления / FLIP-сдвига; `transitionend` ненадёжен в мини-программе, поэтому в первой версии узлы добавляются и удаляются без анимации (имена классов переходов сохранены в источнике стилей и могут быть переиспользованы на H5 с собственным Transition).
- **Клавиатурная семантика кликабельных карточек не перенесена**: plus добавляет `tabindex` и активацию Enter / Space для карточек с `onClick`; у мини-программы нет модели DOM-фокуса, остаются только клик и семантика `role="button"`.
