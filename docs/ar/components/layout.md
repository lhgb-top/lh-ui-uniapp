# Layout تنسيق الحاوية

هيكل الصفحة: `lh-layout` مع المكونات الفرعية `lh-header` / `lh-aside` / `lh-main` / `lh-footer` (مع easycom يمكنك استخدام الوسوم مباشرة؛ عند الاستيراد حسب الحاجة تكون أسماء المكونات `LhLayout` / `LhHeader` / `LhAside` / `LhMain` / `LhFooter`).

## الاستخدام الأساسي (أعلى / محتوى / أسفل)

تحتاج الحاوية إلى ارتفاع صريح: `lh-layout` نفسها حاوية مرنة بقيمة `flex: 1`، لذلك عند وضعها داخل أبٍ في التدفق العادي يجب منحها ارتفاعًا عبر `sx` أو نمط خارجي حتى تتمدد العناصر header / main / footer بالتناسب.

```vue
<template>
  <lh-layout direction="vertical" :sx="{ h: '240px' }">
    <lh-header>الترويسة</lh-header>
    <lh-main>المحتوى</lh-main>
    <lh-footer>التذييل</lh-footer>
  </lh-layout>
</template>
```

## اتجاه الترتيب

يتحكم `direction` بشكل صريح في اتجاه ترتيب العناصر: الافتراضي `horizontal` (جنبًا إلى جنب)، ويتحوّل تلقائيًا إلى `vertical` عند وجود `lh-aside`، ويمكن تحديده يدويًا أيضًا.

```vue
<template>
  <lh-layout direction="horizontal" :sx="{ h: '80px' }">
    <lh-main>جنبًا إلى جنب</lh-main>
    <lh-main>جنبًا إلى جنب</lh-main>
  </lh-layout>
  <lh-layout direction="vertical" :sx="{ h: '140px', mt: '12px' }">
    <lh-main>تراص عمودي</lh-main>
    <lh-main>تراص عمودي</lh-main>
  </lh-layout>
</template>
```

## تنسيق مع شريط جانبي

عند وجود `lh-aside` يتحوّل الأب تلقائيًا إلى الاتجاه العمودي (header في الأعلى، و aside و main جنبًا إلى جنب).

```vue
<template>
  <lh-layout direction="vertical" :sx="{ h: '240px' }">
    <lh-header>الترويسة</lh-header>
    <lh-layout :sx="{ flex: '1', minHeight: '0px' }">
      <lh-aside :width="140" aria-label="التنقل الجانبي">الشريط الجانبي</lh-aside>
      <lh-main>المحتوى</lh-main>
    </lh-layout>
    <lh-footer>التذييل</lh-footer>
  </lh-layout>
</template>
```

يقبل `width` قيمة `number` (تُفسَّر بالبكسل) أو `string` مع وحدة (مثل `'30%'`)؛ عند حذفه يُستخدم `--lh-layout-aside-width` (220px افتراضيًا).

## فروقات المنصة

- **مكون تنسيق CSS بحت**: لا يوجد وحدة layout في share core، وطبقة المنطق تحمل سياق provide/inject فقط (يتحوّل الأب إلى العمودي بمجرد تسجيل Aside)، دون قياس أو طبقات عائمة أو اعتماد على document؛ والسلوك متطابق بين H5 وتطبيق WeChat المصغر.
- **استبدال الوسوم**: وسوم `<section>` / `<header>` / `<aside>` / `<main>` / `<footer>` في نسخة plus تُستبدل كلها بعناصر `view` (WXSS يحرّم منتقي الوسوم، وتُطبَّق الأنماط عبر أسماء الأصناف `lh-layout*`).
- **دلالات المعالم (landmark)**: أدوار المعالم التي توفّرها الوسوم الدلالية طبيعيًا يُستعاد عنها بأسماء `role` — header يعطي `banner`، و aside يعطي `complementary`، و main يعطي `main`، و footer يعطي `contentinfo`؛ عند استخدام عدة عناصر `aside` يُستحسن التمييز بينها عبر `ariaLabel` (مثل "التنقل الجانبي"، "روابط ذات صلة").
- **حاويات التمرير**: قيمة `overflow: auto` لكل من `lh-main` و `lh-aside` تجعل التمرير داخل العنصر نفسه على H5؛ **صفحة التطبيق المصغر ليس لها حاوية body قابلة للتمرير** (يتولّى التمريرَ العقدة الجذر `page`)، فإذا وضعت محتوى الصفحة كاملًا داخل `lh-main` في التطبيق المصغر فقد يتركّب تمرير العنصر وتمرير الصفحة ويسببان شريطي تمرير. لتخطيط صفحة كاملة مع شريط جانبي يُستحسن منح الغلاف الخارجي `h: '100vh'` ليتمرير `lh-main` بنفسه؛ أو لفّ المحتوى داخل `scroll-view` عند الحاجة.
- **خلاصة النقل**: متاح على جميع المنصات بسلوك مطابق لنسخة plus؛ وما يستدعي الانتباه هو دلالة الحاوية «التمرير على مستوى الصفحة مقابل مستوى العنصر» في التطبيقات المصغرة فقط.

::: tip الفروقات عن نسخة Vue 3
- الوسوم الدلالية مستبدلة بـ `view` مع سمات `role` (WXSS يحرّم منتقي الوسوم) مع الحفاظ على دلالات الوصول.
- وسوم المكونات الفرعية تتبع اصطلاح easycom: `lh-header` / `lh-aside` / `lh-main` / `lh-footer` (عند الاستيراد حسب الحاجة تكون الأسماء المقابلة `LhHeader` وغيرها).
- أُضيفت خاصية `customClass`: في uni-app لا تخترق الأصناف العادية `styleIsolation`، لذا تُمرَّر الأصناف المخصصة عبر الخاصية (نسخة plus تمرّر الصنف مباشرة).
- اتجاه الترتيب وآلية provide/inject لتحويل Aside إلى العمودي مطابقة تمامًا لنسخة plus.
:::
