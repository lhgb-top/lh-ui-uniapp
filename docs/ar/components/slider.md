# Slider شريط التمرير

شريط تمرير يتيح اختيار قيمة عن طريق سحب المقبض على طول المسار. يدعم وضع المقبض الفردي ووضيع النطاق (مقبضان)، والالتقاط بخطوة `step`، وعلامات `marks`. يتم رسم المسار والمقابض وشريء التعبئة بالكامل باستخدام `view`، بينما تأتي عمليات تقييم القيمة والالتقاط بالخطوات وترتيب العلامات وعقد إمكانية الوصول مباشرةً من الدوال النقية في `@lh-ui/share` (دون نسخ).

## الاستخدام الأساسي

```vue
<template>
  <lh-slider v-model="value" />
</template>

<script setup lang="ts">
import { ref } from 'vue'
const value = ref(30)
</script>
```

عند عدم تمرير `modelValue` تتم تهيئة الحالة الداخلية بقيمة `min`، وتمريرها يجعل المكوّن مُتحكَّماً به (مثل مكوّنات النموذج الأخرى). أثناء السحب تُحدَّث الحالة الداخلية فقط، ويُرسَل `update:modelValue` / `change` **مرّة واحدة عند الإفلات** (مثل إصدار Vue3).

## اختيار النطاق

يفعّل `range` وضع المقبضين، وتكون `modelValue` عبارة عن زوج `[البداية، النهاية]`:

```vue
<template>
  <lh-slider v-model="span" range />
</template>

<script setup lang="ts">
import { ref } from 'vue'
const span = ref<[number, number]>([20, 60])
</script>
```

عند سحب أحد الطرفين متجاوزاً الطرف الآخر يتم تبديل الطرفين (المقبض الذي تحت الإصبع هو دائماً ما يُسحب)، فتبقى القيمة دائماً `[الأقدم، الأحدث].

## الخطوة والعلامات

يجعل `step` المقبض يلتقط بخطوة الشبكة؛ ويرسم `marks` علامات من خريطة `قيمة → نص` (مرتّبة حسب القيمة):

```vue
<template>
  <lh-slider v-model="value" :min="0" :max="100" :step="10" :marks="marks" />
</template>

<script setup lang="ts">
import { ref } from 'vue'
const value = ref(30)
const marks: Record<number, string> = {
  0: '0',
  50: 'النصف',
  100: 'الأقصى',
}
</script>
```

## التعطيل

يعطّل `disabled` السحب والتنقّل باللوحة المفاتيح ويُخرج المقبض من ترتيب التبويب:

```vue
<template>
  <lh-slider v-model="value" disabled />
</template>
```

## عرض القيمة

يعرض `show-input` القيمة الحالية يمين المسار (في وضع النطاق: نص `[البداية، النهاية]`):

```vue
<template>
  <lh-slider v-model="value" show-input />
</template>
```

## Slider API

### Props

| الخاصية | الوصف | النوع | الافتراضي |
| --- | --- | --- | --- |
| modelValue | القيمة الحالية (v-model مُتحكَّم به؛ زوج في وضع النطاق) | `number \| [number, number]` | — |
| min | الحد الأدنى | `number` | `0` |
| max | الحد الأقصى | `number` | `100` |
| step | حجم الخطوة (أصغر وحدة التقاط للمقبض) | `number` | `1` |
| disabled | تعطيل المكوّن بالكامل | `boolean` | `false` |
| range | وضع النطاق (مقبضان) | `boolean` | `false` |
| showInput | عرض القيمة الحالية بجانب المسار | `boolean` | `false` |
| size | الحجم | `'small' \| 'medium' \| 'large'` | `'medium'` |
| marks | علامات سِمَة (المفاتيح هي القيم، مرتّبة تصاعدياً) | `Record<number, string>` | — |
| customClass | صنف مخصّص يُمرَّر إلى العقدة الجذر | `string` | — |
| sx | خصائص التخطيط السريعة (تُطبَّق على العقدة الجذر) | `LhSxProps` | — |

### Events

| الحدث | الوصف | المعاملات |
| --- | --- | --- |
| update:modelValue | تغيّرت القيمة (v-model؛ تُرسل عند الإفلات أو عند الخطو باللوحة المفاتيح) | `(value: number \| [number, number])` |
| change | تغيّرت القيمة (نفس حمولة update:modelValue) | `(value: number \| [number, number])` |

### إمكانية الوصول

- المقبض هو `role="slider"` مع `aria-valuemin` / `aria-valuemax` / `aria-valuenow` / `aria-valuetext` (العقد يحدّده `getSliderThumbAria` من share)
- في وضع النطاق يحمل المقبحان `aria-label` مختلفين («مقبض البداية / مقبض النهاية»، مفتاحا اللغة `slider.thumbStart` / `slider.thumbEnd`، وإلا فمفتاح `slider.thumb`)
- التنقّل باللوحة المفاتيح (الأسهم تتحرّك بمقدار `step`، وPageUp / PageDown خطوات أكبر، وHome / End تقفز إلى الطرفين) يعمل في H5 فقط، انظر اختلافات المنصّة أدناه

::: tip اختلافات المنصّة (الاختلافات عن إصدار Vue3)
- **حامل السحب**: يربط plus حدثي `mousedown` / `touchstart` على المقبض ثم ينقل استماعَي move / up إلى `document`؛ وليس للبرنامج المصغّر document، لذلك يبقى `touchstart` / `touchmove` / `touchend` مرتبطاً بالمقبض نفسه ( تستمر أحداث touch في البرنامج المصغّر بالوصول إلى هدف touchstart، فلا حاجة لاستماع عام). ويُبقي H5 استماع الفأرة على مستوى document (بعد الضغط يتواصل السحب خارج المكوّن)، يحرسه الترجمة الشرطية، ولا يحتوي حزمة MP على أي كود ميت.
- **حساب الموضع غير متزامن**: يقيس plus المسار باستخدام `getBoundingClientRect` المتزامن؛ وليس للبرنامج المصغّر سوى `createSelectorQuery` غير المتزامن، لذا يستخدم هذا المكوّن `getSingleLhRect` من طبقة المحوّل. تُخزَّن نتيجة القياس لكل جلسة سحب (تُُسخَّن عند touchstart)، لذا لا يكاد السحب العادي يتأثر؛ غير أن تحديث القيمة يتأخر إطاراً واحداً عن اللمس من حيث الدلالة. **لا تفترض داخل حدث move أن القيمة تحدّثت بشكل متزامن**؛ يقع الإرسال عند الإفلات فقط.
- **يُتجاوز عندما يكون عرض المسار صفراً**: عندما لا يكون التخطيط جاهزاً بعد (أو في بيئة الاختبار) يكون عرض مستطيل المسار صفراً، فيُنتج القسمة على صفر قيمة NaN؛ لذا يُتجاوز هذا التحديث بدلاً من تلويث القيمة.
- **التنقّل باللوحة المفاتيح في H5 فقط**: ليس للبرنامج المصغّر أحداث لوحة مفاتيح للخطو بالأسهم / Home / End / PageUp / PageDown، فيُمنع الاستدعاء بالترجمة الشرطية تماماً، ولا يحتوي حزمة MP على كود ميت.
- **تُربط سمات aria فراداً بشكل صريح**: لا يمكن نشر حزمة `LhAriaAttrs` من share عبر `v-bind` (مترجم قوالب MP لا يدعم ذلك)، فتقوم طبقة الغراء بتوسيع مفاتيح `aria-*` إلى روابط صريحة، لكن العقد يبقى بيد الدوال النقية في share.
- **لا وضع عمودي ولا فقاعة tooltip**: لا يحتوي مصدر plus على خاصية `vertical` (مسار عمودي) ولا فقاعة tooltip؛ ويلتزم هذا النقل بالمواءمة الصارمة دون إضافة أي منهما. إن احتجت مساراً عمودياً يمكنك تدوير حاوية خارجية (مع معالجة إحداثيات اللمس بنفسك)، وإن احتجت عرض القيمة استخدم `show-input` لتبقى ظاهرة دائماً.
:::
